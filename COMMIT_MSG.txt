Version the asset URLs: the cache fix was itself in a cached file

Yesterday's change stopped macro.json being cached for seven days. It could not
take effect, because it lives in assets/js/main.js - which the same seven-day
rule was caching. Any browser that had loaded the site before was still running
last week's script and holding last week's figures, and would have done for up
to a week. That is why the July inflation figure still read 15.91% on screen
after the correction had been published, deployed and verified on the server.

All twelve pages now reference assets/js/main.js?v=2026-08-27 and
assets/css/style.css?v=2026-08-27. HTML is served with max-age=0, so the new
HTML arrives immediately and points at a URL no browser has cached, which forces
a fresh fetch of the code - and the code then fetches the figures with no-store.

/assets/js/ and /assets/css/ also drop from seven days to one hour with
revalidation, as a safety net for a forgotten version bump. Images and fonts
keep the seven-day rule.

Bump the ?v= date whenever style.css or main.js changes.
