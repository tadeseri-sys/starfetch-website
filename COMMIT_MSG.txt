Fetch the figures on a unique URL - no-store cannot reach a shared cache

Two days after the July inflation correction was published, deployed and
verified on the server, the live data file was still returning June's 15.91%
when fetched with a fresh query string. no-store governs the visitor's own
browser cache. It has no authority over a shared cache between the visitor and
Netlify, and the new five-minute header applies only to objects fetched after
the deploy - not to one a shared cache was already holding under the old
seven-day instruction. That copy would have been served until about 2 September.

main.js now requests assets/data/macro.json?t=<timestamp>. A unique URL is the
only thing no cache can answer from memory. The file is ~2KB; fetching it fresh
every page load costs nothing worth measuring.

Asset version bumped to ?v=2026-08-27b across all twelve pages, per the standing
rule, because main.js changed.
